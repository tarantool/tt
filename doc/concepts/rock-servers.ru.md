# Серверы rock-модулей

Зависимости пакета представляют собой rock-модули, которые берутся с серверов
rock-модулей: HTTP(S)-сервера LuaRocks или локального каталога с манифестом
LuaRocks. Вместо манифеста любой из них может публиковать
[индекс rock-модулей](#a-rock-index).

## Выбор серверов {#which-servers}

Список серверов определяется по первому совпадению среди следующих уровней:

1. флаг `--registry` команды (можно указывать несколько раз);
2. переменная `TT_REGISTRIES` (список через запятую);
3. поле `[platform].registries` файла `app.manifest.toml`;
4. встроенные серверы по умолчанию: `https://rocks.tarantool.org/` и
   `https://luarocks.org/`.

Уровни заменяют друг друга, а не объединяются: разрешение зависимостей берёт
rock-модуль с первого сервера, где он нашёлся, поэтому добавление сервера к
значениям по умолчанию изменило бы источник модуля. Относительный путь к
каталогу отсчитывается от текущего каталога для `TT_REGISTRIES` и от каталога
манифеста для записей в манифесте.

Команда `tt registry list` выводит список, который использовала бы команда, и
уровень каждого сервера:

```console
$ tt registry list
URL                           SOURCE
https://rocks.tarantool.org/  default
https://luarocks.org/         default
```

Зависимость может указать собственный сервер: `crud = { version = "1.5.2",
registry = "https://my.mirror/" }`. В таком случае модуль разрешается и
устанавливается только с этого сервера, независимо от общего списка; модули,
от которых он зависит, берутся из общего списка. Каталог в таком свойстве
отсчитывается от каталога манифеста, как и в `[platform].registries`, из
какого бы каталога ни запускалась `tt`.

## Индекс rock-модулей {#a-rock-index}

Сервер может публиковать файл `tt-rocks-index.json` там, где лежал бы его
манифест LuaRocks. Индекс называет каждый файл версии rock-модуля по URL и
указывает его sha256: rock-модуль каждой платформы и, отдельно от них,
rockspec. Сами файлы могут лежать в другом месте, например на страницах
релизов, а индекс - быть файлом в git:

```json
{
  "format": 1,
  "repository": {
    "emmylua": {
      "0.30.0pre1-1": {
        "artifacts": [
          {
            "arch": "linux-x86_64",
            "sha256": "…",
            "size": 19777374,
            "url": "https://github.com/tarantool-contrib/rocks-repo/releases/download/emmylua-0.30.0pre1-1/emmylua-0.30.0pre1-1.linux-x86_64.rock"
          }
        ],
        "rockspec": {
          "sha256": "…",
          "url": "emmylua-0.30.0pre1-1.rockspec"
        }
      }
    }
  }
}
```

`url` - абсолютный адрес `https` или путь относительно каталога индекса;
последний сегмент пути совпадает с именем файла:
`<name>-<version>.<arch>.rock` или `<name>-<version>.rockspec`. Незнакомые tt
поля игнорируются; индекс более нового `format` - ошибка с советом обновить
tt.

tt читает индекс раньше любого манифеста, и с HTTP-сервера, и из каталога.
Если индекс есть, он - весь каталог сервера; если он есть, но не читается,
сервер считается неисправным, а не читается через манифесты. С такого
сервера:

- разрешение зависимостей читает rockspec версии, проверив его sha256, и не
  скачивает ни одного rock-модуля;
- локфайл фиксирует sha256 всех файлов версии в поле `artifacts`, рядом с
  `checksum` её исходников:

  ```toml
  [[lock.products.default.dependencies]]
  name = 'emmylua'
  version = '0.30.0pre1-1'
  source = 'registry'
  checksum = 'md5:…'
  artifacts = {linux-x86_64 = 'sha256:…', macosx-aarch64 = 'sha256:…', rockspec = 'sha256:…'}
  ```

- каждая установка rock-модуля - командами `tt package build`,
  `tt package fetch` и `tt test`, а также `tt package install` архива,
  собранного с `--without-deps`, по локфайлу архива - проверяет файл своей
  платформы по этим хешам до распаковки, с какого бы сервера он ни пришёл.
  Несовпадающий файл не устанавливается. Платформа, для которой локфайл не
  фиксирует файла, - тоже ошибка: `tt package resolve` зафиксирует файлы,
  которые сервер отдаёт сейчас.

## Поиск {#searching}

Команда `tt package search TERM` опрашивает каждый сервер в поисках
rock-модулей, чьё имя содержит TERM, и выводит все версии, которые предлагает
каждый из них. В отличие от разрешения зависимостей, поиск не останавливается
на первом сервере.

## Зеркало для офлайн-сборки {#a-mirror-for-offline-builds}

Команда `tt package download --dir DIR` скачивает rock-модули в DIR и
индексирует их, превращая каталог DIR в полноценный сервер rock-модулей. Без
аргументов она зеркалирует зафиксированные зависимости проекта в их точных
версиях, включая dev-зависимости; если переданы имена, скачиваются указанные
модули.

```console
$ tt package download --dir ./vendor-rocks
$ TT_REGISTRIES=./vendor-rocks tt package build
```

Повторный запуск дополняет зеркало на месте. Зависимость не с сервера
rock-модулей - например, заданная через `path` - не имеет rock-модуля для
зеркалирования и пропускается с предупреждением.

Команда `tt wasm rock` собирает сервер такого же вида для rock-модуля `wasm`
из tarantool-wasm: rock-модули релиза для каждой платформы вместе с индексом;
см. [Run WebAssembly components](../how-to/wasm-components.md#share-the-rock).

## tt rocks {#tt-rocks}

Команда `tt rocks` запускает сам LuaRocks для действий, у которых нет
аналогов в `tt package`. Если заданы `TT_REGISTRIES` или манифест, она
обращается к их серверам вместо собственных серверов по умолчанию.
Rock-модуль с частью на C собирается с заголовками того Tarantool, под
которым он запускается: из каталога `.tarantool/include/tarantool` проекта, из
`TT_CLI_TARANTOOL_PREFIX` или из префикса установки этого Tarantool.
