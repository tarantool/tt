# instances.yaml

Описание того, что работает на хосте: половина пары, по которой запускается
приложение, рядом с кластерной конфигурацией `config.yaml`. Находится в
`.templates/<name>/` проекта или пакета либо в `<root>/etc/<app>/` для пары
хоста. См. [Инстансы](../concepts/instances.md).

```yaml
"*":
  restart: on-failure
router-001:
  restart: always
  stop_timeout: 60s
gateway:
  binary: gateway
  args: [--port, "8080"]
  env: {GATEWAY_MODE: production}
  logrotate_signal: SIGHUP
legacy:
  script: init.lua
```

Документ сопоставляет имена инстансов с записями. Имя без записи,
`storage-001:`, задаёт инстанс Tarantool со значениями всех полей по
умолчанию. Инстансы запускаются в том порядке, в котором они записаны;
инстансы, заменяющие собой `"*"`, встают на её место по порядку своих имён.

Имя инстанса не может быть пустым, `.` или `..`, а также содержать слэш или
управляющий символ: оно задаёт имена каталогов инстанса. Алиасы и ключи
слияния YAML не поддерживаются.

## Вид записи {#the-kind-of-a-record}

| Запись | Вид |
| --- | --- |
| без `binary` и без `script` | инстанс Tarantool, настроенный кластерной конфигурацией; должен присутствовать в топологии `config.yaml` |
| `script` | инстанс Tarantool, настраиваемый своим скриптом; см. [Запуск приложения на box.cfg](../how-to/script-instances.md) |
| `binary` | внешний процесс; см. [Запуск внешнего процесса](../how-to/external-processes.md) |

Поля `binary` и `script` взаимоисключающие. Ни инстанс со скриптом, ни
внешний процесс не могут называться именем инстанса из топологии.

Запись `"*"` - в кавычках, поскольку отдельный символ `*` является алиасом
YAML - обозначает каждый инстанс топологии, для которого нет другой записи.
Она не может содержать `binary` или `script`. Запись конкретного инстанса из
топологии полностью заменяет собой `"*"`, не наследуя ни одного её поля.

## Поля {#fields}

| Поле | Виды | По умолчанию | |
| --- | --- | --- | --- |
| `restart` | все | `no` | `no`, `on-failure` или `always`: когда watchdog снова запускает инстанс после его самостоятельного завершения |
| `stop_signal` | все | `SIGTERM` | сигнал, отправляемый при останове: `SIGINT` или `INT` |
| `stop_timeout` | все | `30s` | сколько времени ожидать перед принудительным завершением инстанса; положительная длительность, например `10s` или `1m30s` |
| `env` | все | | переменные окружения, накладываемые поверх окружения tt |
| `script` | script | | скрипт на Lua, относительно каталога приложения |
| `binary` | external | | программа: путь относительно каталога приложения, если он содержит слэш; иначе имя программы, которое ищется в `.rocks/bin/` приложения, а затем в `PATH` |
| `args` | external | | аргументы программы, список строк |
| `workdir` | external | каталог данных | рабочий каталог относительно каталога приложения |
| `logrotate_signal` | external | нет | сигнал, который `tt instance logrotate` отправляет процессу |

Под systemd `restart` становится директивой `Restart=` юнита, а `stop_timeout`
- его `TimeoutStopSec=`; см.
[Запуск инстансов под systemd](../how-to/systemd.md).

С флагом `--integrity-check` секция `env` у инстанса Tarantool отвергается:
эти значения должны находиться в кластерной конфигурации. См.
[Подпись пакетов](../how-to/sign-packages.md#the-layout-on-tarantool-enterprise).
