# tt.manifest.toml

Манифест [дистрибутива tt](../how-to/build-distribution.md): ядро tt и
модули tt, которые `tt binary build tt` компилирует в один бинарный файл.
Сборка записывает рядом с ним `tt.manifest.lock` и `tt.manifest.sum`.

```toml
manifest_version = "0.1"
manifest_kind = "tt-distribution"

[package]
name = "tt"

[core]
tt = "v3.0.0-alpha.2"

[distribution]
title = "Tarantool CLI EE"
edition = "ee"
integrity = "rsa"
builtin = true
external_modules = true
bundle_sources = ["customer-zone"]

[build]
ssl = "openssl_static"
tags = ["netgo"]

[dependencies]
aeon = "github.com/tarantool/tt/modules/aeon"
probe = "../tt-probe"
foo = "github.com/acme/tt-foo@v1.2.0"
bar = { module = "github.com/acme/tools", version = "v0.3.0", package = "github.com/acme/tools/ttbar", symbol = "Commands" }

[replace]
"example.com/lib" = "./libs/lib"
"github.com/acme/lib/v2" = "github.com/acme/lib/v2@main"
```

Обязательны только `manifest_version` и `manifest_kind`: минимальный
манифест собирает сам tt на ядре того tt, который запускает сборку.
Неизвестное поле считается ошибкой, если только в манифесте не объявлена
более новая минорная версия `manifest_version`, чем известна tt, - в этом
случае выводится предупреждение. Другая мажорная версия отвергается.

## Верхний уровень {#top-level}

| Поле | Обязательно | |
| --- | --- | --- |
| `manifest_version` | да | версия формата: `"0.1"` |
| `manifest_kind` | да | `"tt-distribution"`; манифест без него - это манифест приложения, `app.manifest.toml` |

## `[package]` {#package}

| Поле | По умолчанию | |
| --- | --- | --- |
| `name` | `tt` | имя бинарного файла: буквы, цифры, `.`, `_` и `-`, начинается с буквы или цифры |

## `[core]` {#core}

Ядро tt, на котором собирается бинарный файл. Поля `tt` и `path` взаимоисключают друг друга.

| Поле | По умолчанию | |
| --- | --- | --- |
| `tt` | версия ядра того tt, который запускает сборку | запрос версии Go для модуля ядра |
| `path` | | локальный чекаут tt относительно каталога манифеста |
| `module` | `github.com/tarantool/tt/v3` | Go-модуль ядра для форка; чекаут `path` должен содержать его |

`tt` разрешается командой go как `go list -m <module>@<tt>`:

- версия, например `v3.0.0-alpha.2`;
- хеш коммита для коммита, на который не указывает ни один тег;
- `latest`: самый новый релиз или самый новый пре-релиз, пока релизов нет;
- префикс, например `v3` или `v3.1`: самый новый релиз с этим префиксом.
  Go воспринимает `v3` как префикс версии, но никогда как ветку `v3`, а
  префикс не соответствует ни одному пре-релизу: пока у tt 3 есть только
  пре-релизы, `v3` не соответствует ничему;
- сравнение, например `<v3.1.0`;
- ветка или тег, имя которого не является версией.

Lock-файл фиксирует то, во что разрешился запрос, до запуска с `--update`.
В любом случае лучше зафиксировать точную версию или коммит, чтобы при
`--update` и при сборке без lock-файла бралось то, что указано в
манифесте.

Без `tt` сборка с помощью tt, версию которого Go не может загрузить
(сборка для разработки), завершается с ошибкой: укажите `tt` или `path`.
Флаг `--core` и переменная `TT_DIST_CORE` переопределяют секцию `[core]` на
одну сборку (см.
[Сборка на другом ядре](../how-to/build-distribution.md#building-on-another-core)).

## `[distribution]` {#distribution}

Как бинарный файл представляет себя и что в нём есть помимо модулей.

| Поле | По умолчанию | |
| --- | --- | --- |
| `title` | `Tarantool CLI` | имя, под которым бинарный файл представляет себя в справке и в `tt version` |
| `edition` | нет | метаданные сборки semver после короткой версии: `ee` превращает её в `3.1.0+ee` |
| `integrity` | `none` | провайдер целостности: `none` или `rsa` (см. [Подпись пакетов](../how-to/sign-packages.md)) |
| `builtin` | `true` | собственные команды tt, модуль `builtin` |
| `external_modules` | `true` | [внешние модули](../how-to/external-modules.md) и `tt modules` |
| `bundle_sources` | `["customer-zone"]` | откуда `tt binary install` и `tt binary search` берут Tarantool Enterprise, SDK, TCM и tt-ee, по порядку: `customer-zone` - личный кабинет tarantool.io, с флагом `--credentials-file`; `[]` - ни одного источника, и эти продукты ставятся только из `--local-dir` |

Версия дистрибутива берётся из `git describe` в каталоге манифеста; за ней
следует `VERSION_LABEL`.

## `[build]` {#build}

Как компилируется бинарный файл. Lock-файл не сохраняет эти параметры:
один lock-файл подходит для сборки любым способом.

| Поле | По умолчанию | |
| --- | --- | --- |
| `ssl` | `default` | реализация TLS: `default`, `openssl` или `openssl_static`; `TT_CLI_BUILD_SSL` переопределяет её |
| `cgo` | включён только для `openssl` и `openssl_static` | собирать с cgo |
| `tags` | нет | теги сборки, добавляемые к тегам реализации TLS; без запятых и пробелов |
| `ldflags` | нет | флаги линковщика, добавляемые после собственных флагов tt, по одному флагу на запись |

## `[dependencies]` {#dependencies}

Модули tt по именам. Имя - это имя модуля в tt: в `tt version --modules`, в
его записях журнала и в ошибках его команд. Буква, за которой следуют буквы,
цифры, `-` и `_`. Имя `builtin` занято, пока включён
`[distribution].builtin`.

Модуль задаётся строкой или таблицей. Строка представляет собой одно из:

- локальный каталог: `.`, `..` или путь, начинающийся с `./`, `../` или
  `/`, относительно каталога манифеста;
- путь Go-модуля: `github.com/tarantool/tt/modules/aeon`;
- путь Go-модуля и запрос версии после `@`:
  `github.com/acme/tt-foo@v1.2.0`.

У таблицы следующие поля:

| Поле | По умолчанию | |
| --- | --- | --- |
| `module` | из `go.mod` в `path` | путь Go-модуля; обязателен без `path` и должен совпадать с `go.mod` при его наличии |
| `version` | коммит ядра для модуля из репозитория ядра, `latest` для любого другого | запрос версии Go; не допускается вместе с `path`, а также для модуля из репозитория ядра, который следует за ядром |
| `path` | | локальный каталог с модулем относительно каталога манифеста |
| `package` | корневой пакет модуля | путь импорта пакета с конструктором; пакет из `module` |
| `symbol` | `New` | конструктор: экспортируемый идентификатор с типом `func(sdk.Services) []sdk.Mount` |
| `kind` | `tt-module` | единственный существующий тип |
| `source` | `path` при указанном `path`, иначе `registry` | |

SDK-модули, требуемые модулем, берутся из ядра - на его коммите или из его
чекаута, - что бы ни было указано в `go.mod` самого модуля (см.
[Написание модуля tt](../how-to/write-a-module.md#set-up-the-go-module)).

## `[replace]` {#replace}

Go-модули сборки, берущиеся из другого места, в виде директив `replace`
главного модуля, который генерирует сборка (сам модуль tt задать их не
может). Ключ - это путь Go-модуля, с `@version` для подмены только этой
версии. Значение - локальный каталог (начинается с `./`, `../` или `/`
относительно каталога манифеста), содержащий модуль, либо `module@version`,
где версия может быть любым запросом; lock-файл фиксирует то, во что она
разрешилась. Ядро, модули его репозитория и модули из `[dependencies]`
подменять здесь нельзя. Подмена, из которой не берётся ни один пакет сборки,
не действует и выводит предупреждение. См.
[Подмена модулей Go](../how-to/build-distribution.md#replacing-go-modules).
